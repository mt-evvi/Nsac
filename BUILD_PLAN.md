# Planet X and SPHEREx build plan

Use this plan for the handoff to a fresh build chat on the same server. The official objective is a public tool where anyone can enter right ascension and declination, then play real SPHEREx images of that patch in time order. NASA names five targets to test. All five belong in the verification matrix. [Official challenge](https://www.spaceappschallenge.org/2026/challenges/planet-x-and-spherex/?tab=details) · [Official challenge content](https://rest.spaceappschallenge.org/api/v2/pages/55120/)

## 1. What to ship

**Required flow.** Open the site without an account, enter a valid sky position, and land on the earliest suitable real image in the chosen date range and wavelength. Play, pause, step, and scrub a timeline marked with real UTC observations. Switch between observation dates, 7-day and 30-day intervals, and published survey passes when pass labels are known. Show gaps and fetch only the selected image and bounded nearby frames. With one usable visit, show that image and explain why playback is unavailable.

**Full feature scope.** Deliver shareable state, field of view, frame metadata, two-date blink and side-by-side, difference and sum, a ranked heatmap of changes, automatic source and candidate recognition, manual mark and compare, bounded future sky-path estimates, Gaia DR3 and AllWISE overlays, and spectra. Limit each analysis to the selected field, dates and source. A vetted fit can produce a forecast. Sparse or ambiguous data produce a visible reason and retain the measured results.

**Release bar.** A signed-out visitor can use all planned flows on suitable example data, try the five named fields, and query at least one covered position outside the presets. Show coverage or quality limitations per target. The examples remain usable during an IRSA outage, and custom queries report their actual status. A static preset copy is a judging contingency with reduced functionality.

**How many dates are available?** A November 14 live wide-survey DR1 + QR3 metadata check counted 39 UTC dates for Barnard’s Star, 60 for Epsilon Indi B, 27 for WISE 0855, 35 for RW Aurigae, and 78 for R Draconis. Longest gaps ranged from 99 to 178 days. These are geometric archive matches. Separate detectors can be simultaneous, and wavelength, footprint and artifact filtering can reduce the number of usable comparison frames. [Observation availability and reproduction](docs/OBSERVATION_AVAILABILITY.md)

## 2. Stack, module boundaries, and API

- **Browser:** Vite and TypeScript, with a canvas or layered images for playback and ordinary HTML controls. Begin with native controls and a shared zoom/pan transform. A second view or Aladin Lite can use the same celestial coordinates later. Keep the image display useful at phone widths and with a keyboard.
- **Backend and batch:** Python 3.12, FastAPI, PyVO or astroquery, Astropy, NumPy, reproject, and Pillow. Use one processing path for interactive queries and batch preparation of examples. Serve the production Vite build and the API over a single HTTPS origin. The installed runtimes and headless Playwright MCP are documented in [DEVELOPMENT.md](DEVELOPMENT.md).
- **Proposed layout:** `web/` for controls and rendering, `server/` for request handling and archive/processing modules, `tools/` for the example-generation command, and `docs/` for provenance and the test matrix. Put pinned app dependencies and setup commands in the repo. The server's `.tooling/` directory is a convenience for this host.
- **Input:** Two labeled fields with decimal degrees or sexagesimal examples. Normalize to ICRS degrees before querying. Accept RA in `[0, 360)` or in hours for sexagesimal input. Validate declination in `[-90, 90]`, finite input, minute/second bounds, and the sign on declinations such as `-00d30m`. Accept the Unicode minus in copied coordinates. Handle wrap near RA zero and the poles using spherical geometry. Default to a 3′ square within a 1′–8′ range.
- **Integration:** `POST /api/v1/series` discovers bounded metadata. `POST /api/v1/series/{seriesId}/frames/{frameId}` prepares one frame. Cache hits return immediately. Async work uses `GET /api/v1/jobs/{jobId}`. Match preset and live manifest shapes. The [viewer and API specification](docs/VIEWER_AND_API.md) gives routes, payloads, timeline behavior, share state and client checks.
- **Science:** The [comparison and tracking specification](docs/COMPARISON_AND_TRACKING.md) gives the algorithms, calibrations, model requirements, and acceptance tests for detection, comparison, forecast, overlay, and spectrum.
- **Capacity:** The [production and budgets specification](docs/PRODUCTION_AND_BUDGETS.md) is authoritative for numerical ceilings, queues, cache, deployment and rollback.

## 3. Archive and image pipeline

1. **Prove archive access first.** Query IRSA SIA2 for the DR1 and QR3 wide survey collections (`spherex_dr1` and `spherex_qr3`). DR1 covers surveys 1 and 2 and QR3 covers surveys 3 and 4. Query by sky footprint and use separate time windows when needed so a row limit cannot return only one visit. The newest calibrated imagery supersedes QR2. Keep collection names in configuration so later releases can be added deliberately. A metadata-driven query can find newer observations without a frontend change. [IRSA release guide](https://irsa.ipac.caltech.edu/spherex-archive-documentation/spherex-data-releases/) · [IRSA access guide](https://irsa.ipac.caltech.edu/spherex-archive-documentation/spherex-data-access/)
2. **Find independent visits.** Parse footprint, observation timestamps, ID, detector, bandpass and release from the results. An observation ID can be shared by simultaneous images from multiple detectors. Deduplicate by product ID, count pointings and actual UTC observation dates, and construct visit groups separately for analysis. Verify candidate times and coverage against the final FITS. Prepare the earliest suitable date on first view. Subsequent frames are prepared only as requested or prefetched within the budget. Select two matched epochs for the first proof and at least three usable independent visits for the first validated forecasting example.
3. **Request cutouts and cap work.** Request small on-premises cutouts through IRSA using the returned official FITS URL, position, and size. Accept only expected HTTPS archive endpoints, including after redirects. Read `IMAGE`, `FLAGS`, `VARIANCE` and the spatial/spectral WCS. The IRSA cutouts may carry a large PSF extension even for a tiny field. Measure downloaded bytes and elapsed time in the first spike, then set limits on candidates, downloads, bytes, field width, workers and elapsed time. Use bounded retries for transient failures and cache the processed results. [IRSA cutout guide](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/cutout_tool.html) · [IRSA notebooks](https://caltech-ipac.github.io/irsa-tutorials/spherex/)
4. **Match wavelength before comparing.** SPHEREx's filters vary across a detector. Use the original pixel WCS at the requested sky position to obtain central wavelength and bandwidth. Use SIA detector/band metadata to shortlist exposures. For the visual comparison, select exposures with overlapping passbands and a documented tolerance set against the actual band widths. Permit descriptive single-frame viewing if no comparable series exists. Record the effective values for each frame. Use the archive's calibrated `CWAVE` and `CBAND` products before publishing precision photometry or spectra. [SPHEREx data products](https://irsa.ipac.caltech.edu/spherex-archive-documentation/spherex-data-products/)
5. **Register a fixed field.** Build one north-up ICRS TAN grid for the whole result at close to native sampling. Use Astropy and reproject for image values and resample quality flags with nearest neighbor or a conservative validity mask. Apply documented fatal/saturation masks and track the valid footprint. A nonzero flag can mark a known source, so use the named bit meanings. Show missing coverage distinctly. Check background stars for residual misalignment before publishing a motion example. Disable scientific comparisons if the overlap or alignment fails. Keep the grid fixed for movers and use one robust intensity stretch across each comparable sequence. Use the original aligned calibrated arrays for comparisons. [SPHEREx data products](https://irsa.ipac.caltech.edu/spherex-archive-documentation/spherex-data-products/) · [IRSA spectrophotometry guide](https://irsa.ipac.caltech.edu/onlinehelp/spherex/spherex/sp.html)
6. **Export lightweight frames.** Publish derived images, metadata, and an attribution link. Preload just the adjacent frames. Start paused and offer a slower playback speed. Label playback as ordered observations and display actual dates and gaps. If time-lapse frames were coadded, show the contributing range. Bundle verified real examples or documented coverage outcomes as local static assets served by the production build. Keep that route working when the live API or archive is offline.

**Evidence already collected.** A DR1 D6 cutout at RA 269.45°, Dec +4.768° was about 4 MB at 0.05° and parsed as a 29 × 29 image with an observation time and spectral WCS. The newer metadata probe found 39 raw dates at that center. Some metadata requests returned HTTP 502 and a bounded retry recovered. Reuse that field for the first build spike, then prove two wavelength-compatible visits, usable source signal and alignment. [Verified IRSA cutout](https://irsa.ipac.caltech.edu/ibe/data/spherex/dr1/level2/2025W33_2C/l2b-v27-2026-228/6/level2_2025W33_2C_0321_1D6_spx_l2b-v27-2026-228.fits?center=269.45,4.768&size=0.05) · [Live counts and limits](docs/OBSERVATION_AVAILABILITY.md)

## 4. Viewer states and interaction

1. Open with a clear explanation of RA/Dec, input examples, and five preset buttons. A real verified example should be one click away during judging.
2. While loading, show the active coordinates and whether the app is searching, fetching or aligning. Cancel or ignore superseded results. On success show a date strip, play/pause, stepping, speed and a frame details panel. Preserve zoom and the marker location when changing frame.
3. Distinguish successful playback, a single image, few or no comparable epochs, a cutout with masked pixels, and a retryable service error. Preserve the user's query on errors. Allow explicit navigation to a cached example while showing which example was loaded.
4. Encode normalized `ra`, `dec`, optional `fov`, and comparison settings in the URL. Restore that query on reload and in a fresh browser. Validate malformed parameters as ordinary input errors. After direct links pass, decide if third-party iframe embedding deserves dedicated support.

## 5. Verify all five official targets

Store the resolver or catalog identifier, ICRS position and reference epoch, and source for each preset. Use proper motion where available to center a fixed observation-era field. Never treat an epoch-propagated marker as a detection. High proper motion over multiple years can put old coordinates outside a small field. Astropy can propagate catalog proper motion, with annual parallax treated separately if precision requires it. [Astropy space motion](https://docs.astropy.org/en/stable/coordinates/apply_space_motion.html)

| Target | Data and acceptance check |
|---|---|
| Barnard’s Star | Resolve HIP 87937 and correct its historical position for the observation period. Look for displacement relative to stationary field stars across the longest usable baseline. Its proper motion is about 10″ per year, so check for sub-pixel shifts on short baselines and for saturation before making a motion claim. [SIMBAD](https://simbad.u-strasbg.fr/simbad/sim-id?Ident=HIP+87937&bibdisplay=none&protocol=html) |
| Epsilon Indi B | Resolve the Ba/Bb system separately from ε Indi A using `2MASS J22041052-5646577` and the published reference epoch. Verify the modern field and test combined-source displacement. The binary pair is below the native pixel scale. [System astrometry](https://www.aanda.org/articles/aa/pdf/2004/03/aa0292.pdf) |
| WISE 0855 | Test NASA’s literal coordinate input (`08h55m10.831s`, `−7d14m42.53s`) and a separately labeled epoch-corrected preset from catalog astrometry. Its expected 2026 position is roughly 2′ west of the supplied seed, so use a wider field to include both. Try matched D6 exposures near 4.5 µm if available. The object is faint. Record a non-detection when the data warrant it. [Catalog astrometry](https://simbad.harvard.edu/simbad/sim-id?Ident=WISE+J085510.83-071442.5+) · [Discovery paper](https://doi.org/10.1088/2041-8205/786/2/L18) |
| RW Aurigae | Verify the AAVSO catalog position and compare brightness at the same location and wavelength. Consider saturation and blended light from the binary. [AAVSO VSX](https://vsx.aavso.org/index.php?revid=418953&view=detail.top) · [Binary study](https://academic.oup.com/mnras/article/497/4/4322/5895909) |
| R Draconis | Use the AAVSO coordinates and compare available near-infrared epochs for brightness change at a fixed location. Sparse coverage can limit any variability conclusion. [AAVSO coordinates](https://archive.aavso.org/index.php/aavso-bulletin-coordinates) |

Deliver a test matrix with the input and resolved coordinates, reference epoch, release, observation IDs, UTC dates, usable frame count, baseline, wavelength/quality, and actual outcome for each target. Distinguish no sky coverage, no comparable images, effects of masking, no detectable signal or change, and observed change. Demonstrate the strongest verified example in the video or slides.

## 6. Full feature backlog and release checks

| Priority | Feature | Gate |
|---|---|---|
| Foundation | Share links, field of view, metadata and intervals | A signed-out shared link restores the query and selected dates or reports that a pinned source is unavailable. The width updates the cutout. The details panel shows dates, wavelength, coverage, artifacts and provenance. |
| Foundation | Blink and side-by-side | Choose any available pair, show both dates and compatibility, and keep the geometry and contrast synchronized. Wavelength-incompatible pairs can be inspected with a visible warning. Keyboard controls and mobile layout pass. |
| Compare | Difference heatmap and sum | For a compatible pair, compute signed B−A, absolute change, and a separately labeled A+B on calibrated arrays in common valid pixels. Show a strength score only when its assumptions can be explained. Test a stable field for artificial residuals and respect the analysis gate before ranking. |
| Compare | Automatic source recognition and mark and compare | Rank measured motion, brightness-change and ambiguous candidates and explain the evidence. User marks and measured centroids retain provenance. Two dates report angular separation, direction, rate and elapsed time. Shareable marks restore on the same versions of the frames. |
| Track | Possible future path | Fit a sky-plane model only from at least three significant, unambiguous independent visits. Show a limited future horizon and uncertainty. Verify on a held-out epoch. Use validated catalog motion or a vetted ephemeris separately when a known object is reliably identified. |
| Explore | Gaia DR3 and AllWISE overlays | Put catalog positions on the same celestial grid, propagate where appropriate, display catalog identity and reference epoch, and label truncated results and ambiguous associations. Aladin Lite is an optional context panel. [Aladin Lite docs](https://aladin.cds.unistra.fr/AladinLite/doc/) |
| Explore | Detector filters, coadds and on-demand spectra | Filter detector and actual wavelength separately. Coadd within short compatible time/wavelength windows. Extract a bounded calibrated spectrum at a selected source, showing errors, dates and gaps. Validate against IRSA. Separately expose 102-channel coadded DR1 context where a bounded extract is feasible. [IRSA spectrophotometry](https://irsa.ipac.caltech.edu/onlinehelp/spherex/spherex/sp.html) · [DR1 products](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/overview_dr1.html) |

Treat the release adapter in §3 as the plan for new SPHEREx releases. Use WiseView for comparison patterns, Astropy for FITS and coordinates, and the official IRSA tutorials for access. NEOSSat/CADC are optional partner references if the team chooses a validated extension that uses them. The base flow uses SPHEREx. [Challenge resources tab](https://www.spaceappschallenge.org/2026/challenges/planet-x-and-spherex/?tab=resources)

## 7. Build order and acceptance gates

| When | Work | Checkpoint |
|---|---|---|
| First 2 hours | Agree on core UI and the manifest. In parallel, find two usable dates on one field, build a viewer shell from a clearly labeled synthetic fixture, and establish production hosting. | One reproducible query with two dated compatible exposures, one manifest with real derived frames, and a reachable public HTTPS shell. |
| Hours 2–8 | Wire the data pipeline to the viewer and live endpoint. Add simple play/pause/step/scrub, frame metadata, and loading/error states. | A user enters coordinates and plays aligned SPHEREx frames locally and via production. A repeat query uses cached results. |
| Core milestone | Package the five named fields, shared links, metadata, interval controls, and blink. Prove a non-preset query against production. | Test matrix and provenance cover all five. The demo path stays playable during a live-archive outage. |
| Comparison and tracking milestone | Build aligned heatmap/sum and mark and compare, then automatic detection, association and forecasts. Exercise a known quiet field, injected motion and variability, and a held-out epoch. | Real and controlled fixtures pass the comparison, recognition and forecast checks. A poor match has a measured-only or unavailable state. |
| Spectrum and catalog milestone | Add Gaia and AllWISE overlays, compatible coadds, and calibrated spectrum jobs in parallel with release QA. | Overlay positions track the field and epoch. At least one spectrum agrees with an IRSA reference within a documented tolerance. Budget-limited jobs return partial results or a clear reason. |
| Submission freeze | Freeze the verified build roughly three hours before the judging cutoff. Make the demo and give the team the release checklist. | Verify science, the default interaction, all implemented feature paths, desktop/mobile, and signed-out links. State any feature still incomplete at the deadline. The full build acceptance still covers each backlog item. |

**Automated checks.** Test coordinate units and signs, wrap/poles, query encoding, deduplication and visit selection, wavelength matching, WCS registration of synthetic fixed and moving sources, and bad/empty footprints. Test that a transient upstream error does not masquerade as no coverage, and that the viewer restores shared links, plays cached frames, and keeps the most recent result during overlapping queries. Run the live archive smoke separately from deterministic tests.

**Manual checks.** In Playwright, capture desktop and phone-sized screenshots and inspect the rendering. Run keyboard-only playback and check labels, zoom and loading states. In an external signed-out browser, open the deployment directly, play the real examples, paste a share URL, and run the out-of-preset query. Verify display dates and positions against source metadata. Measure cold and warm time to first frame, compare against the first spike, and prioritize the changes that shorten the public demo path.

**Ownership.** Assign owners for archive/science, viewer, public deployment, and demo/submission. People can cover more than one area. Agree on the manifest early so the science and viewer work can proceed in parallel, then test their integration with the real frames before adding features.

## Build-chat handoff

Keep the existing server project in the app. For a fresh CLI session, run `codex -C /srv/nsac/nsac` to set the build working directory and pick up the project Playwright MCP. If opening a fresh chat at the parent directory, direct it to work in `/srv/nsac/nsac` and check that Playwright tools are visible. The activation script is shell-local and can be sourced by absolute path.

Suggested first build prompt:

> Work in /srv/nsac/nsac. Read BUILD_PLAN.md, DEVELOPMENT.md, and the linked specifications in docs/. Build the full scope in milestone order, beginning with a vertical slice that fetches two compatible real SPHEREx visits, aligns them and supports on-demand time-slider playback. Record product IDs, dates and coverage limits. Verify the five required targets, comparison and tracking, overlays, spectra, and resource budgets. Send reviewed project files to mt-evvi/Nsac. Prepare a production release for this server and use the owner-approved hostname and Caddy procedure.
