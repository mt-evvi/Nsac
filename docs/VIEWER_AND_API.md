# Viewer, timeline, and API specification

This is the integration contract for the public Planet X and SPHEREx web tool. [Build plan](../BUILD_PLAN.md) gives the delivery order. [Comparison and tracking](COMPARISON_AND_TRACKING.md) defines the analysis, and [Production and budgets](PRODUCTION_AND_BUDGETS.md) defines the enforced ceilings.

## 1. Visitor flow

1. The entry page has RA, declination, a bounded field-of-view selector, and the five official examples. Accept decimal degrees and sexagesimal input. Show the convention and normalize a Unicode minus. An example opens the same result view as a custom search.
2. Navigate to `/explore` with the normalized coordinates, field width, and any chosen dates or band in the query string. Show the requested field immediately while discovery runs. The result loads the **earliest available suitable frame in that selection** and starts paused. If the oldest metadata candidate fails its FITS footprint or quality check, identify the actual first displayed date. Never silently change to a preset.
3. Keep the main view registered to one north-up celestial grid. Desktop shows the image and inspector together. Mobile keeps the image and slider above collapsible tools. Controls include play/pause, step in either direction, a focusable slider, speed, wavelength, interval, dates, zoom, and a reset view action. Keep frame loading and metadata on screen while the visitor waits.
4. Set up a before/after pair from the currently viewed frame and one compatible comparison date. Two-date blink, side-by-side, signed heatmap, and sum share the pair selector and a single geometry. A dedicated sign legend and before/after dates appear on the heatmap. Expose candidates in a short list that highlights their locations on the image. If registration or wavelength checks fail, keep individual images accessible and explain why pixel comparison is unavailable.
5. **Mark and compare** lets a visitor choose a point in frame A and another in B, optionally snapping to a measured detection. Display angular separation, elapsed time, position angle where defined, and the average apparent angular rate. Retain measurement provenance and show a motion arrow when requested. The tracking panel can seek the source across more usable independent visits and show a short uncertainty-bounded future path when the measurements support one. The overlaid path and the observation slider are separate controls with separate labels.
6. A frame-details panel includes observation UTC start/end, product ID and release, selected band and actual wavelength/bandwidth if computed, mask and contamination/quality notes, and links to the original data. A Gaia/WISE overlay toggle and a spectrum action at the selected source or sky coordinate are both available on demand. Distinguish a spectrum made from exposures at different dates from a per-epoch one. Optional Aladin Lite shows the surrounding sky using the same coordinate conventions and does not drive the main playback. [Aladin Lite API](https://aladin.cds.unistra.fr/AladinLite/doc/API/)

## 2. Timeline counts, ticks, and fetching

Keep these quantities distinct in the manifest and UI.

| Quantity | Meaning |
|---|---|
| Products | Unique detector files matching the search footprint and metadata filters. Simultaneous detectors and repeated rows can occur. |
| Pointings | Unique `obs_id` values with actual timestamps. Distinct pointings in the same visit can be minutes apart. |
| Observation dates | Count of distinct UTC start dates of those pointings, shown as an archive result or as a lower bound if incomplete. |
| Display slots | Nonempty buckets inside the selected date and interval settings. Slots with metadata only are candidates. |
| Usable comparison frames | Cutouts already loaded and validated against the active wavelength, footprint, masks, and registration. Counts can grow as frames are prepared. |
| Independent epochs | Distinct separated visits used in motion/variability analysis. Multiple files or time buckets can still belong to one visit. |

- **Intervals.** Default to **Observation dates (UTC)**. Add **7 days** and **30 days** using deterministic UTC buckets anchored at the start of the selected UTC date range. Also offer **Survey passes** when authoritative survey labels can be assigned. These are grouping controls. Each occupied bucket displays a representative exposure with its **actual** observation time. Empty intervals appear as gaps, and the slider snaps to an occupied slot. A separate detail selector exposes repeated pointings on the same date within the metadata page and caps, including for short-timescale changes. Label a coadd clearly when the visitor selects that alternate representation.
- **Slider.** Use discrete ordered slots rendered against real time, with a native range control or equivalent keyboard-accessible input and a list of dates. Set truthful `aria-valuetext`, preserve focus, and map left/right to previous/next observation. An optional date jump can snap to the nearest available time with a visible notice and the actual time difference. A visit in a gap never gets a synthetic frame. Playback advances among occupied slots at the selected playback speed with actual dates visible throughout.
- **Deterministic selection.** Keep all distinct dates in the bounded metadata view. Group simultaneous detector products by pointing. For analysis, use authoritative visit IDs when available or conservatively cluster consecutive pointings less than 24 hours apart into one visit, including across UTC midnight. Record the grouping method. Prioritize usable footprint, reference wavelength compatibility and quality. Use documented deterministic ties such as earlier UTC timestamp and product ID. A candidate remains pending until validated. If the active band has no suitable frame in a bin, mark that bin as unavailable for comparison and offer individual raw viewing where appropriate. Show counts/warnings for truncated metadata and a way to narrow the range. Keep `NO_COVERAGE`, partial coverage, `NO_COMPARABLE_FRAMES` and transport failure distinct.
- **Lazy loading.** Run bounded metadata discovery first. Prepare the earliest slot only, then load the selected slot on drag release or after a short keyboard debounce. While dragging, update the date label from metadata. Debounce quick changes, abort the browser's superseded request, and use a request generation ID so a late result cannot replace the active selection. The API deduplicates shared jobs. The UI prefetches at most the immediate neighbors, at lower priority after the current frame is visible. Pause playback or skip with a clear message when a future frame is unavailable. Cache prepared immutable assets and enforce memory, bytes and concurrency limits. [Archive access](https://irsa.ipac.caltech.edu/spherex-archive-documentation/spherex-data-access/)
- **Display range.** Lock a robust grayscale stretch for a view session once the first suitable frame is ready, or use the bundled reference stretch for a preset. Dock a manual shared contrast control with reset. Pair comparisons can recalculate a shared range when the visitor changes the pair, and identify that range in the legend. Use one scale across the selected pair, and compute analysis on calibrated arrays before any display stretch. A later fetch does not silently change the active scale.
- **Preparing more dates for tracking.** Analysis uses the already prepared compatible frames first. An explicit **Prepare dates for tracking** action offers actual unprepared visit candidates spread across the range, prioritizing the next independent visit. Show the number of frames before preparation. Queue them through the ordinary per-frame route, one at a time within the session limit, and let the visitor stop between jobs. Run detection and tracking on the prepared subset. A trace may still be unavailable if sources do not match, the compatible time baseline is too short, or the budget runs out.

## 3. HTTP contract

Paths below are same-origin. IDs are server-issued opaque strings, resolving to finite, normalized cache keys, all validated in the context of the referenced series. A path parameter never becomes a filename or upstream URL without lookup. UI labels and API errors use controlled strings. Payloads with malformed or unknown fields fail validation. Production byte/time/queue limits are authoritative.

| Endpoint | Inputs and behavior |
|---|---|
| `GET /healthz`, `GET /readyz` | Liveness and readiness. Liveness is local only. Readiness checks installed/static assets and local writable state, and can report the last bounded archive probe separately. |
| `POST /api/v1/series` | `raDeg`, `decDeg`, `fovArcmin`, optional UTC `start`/`end` and optional band/wavelength selection. Default to the most recent 24 months of published mission coverage, limited to actual mission dates, and cap each public request to 24 months. Discover metadata and return a manifest or an async job. A date interval and display mode are viewer settings that reuse discovery unless further coverage is requested. |
| `GET /api/v1/series/{seriesId}` | Current discovery state or a capped page of already indexed entries using a server-issued cursor. No upstream fan-out. A partial archive index can be refined with a narrower date range through a new discovery request. |
| `GET /api/v1/series/{seriesId}/frames/{frameId}` | Read status/metadata for one advertised candidate; prepared assets have immutable relative URLs. |
| `POST /api/v1/series/{seriesId}/frames/{frameId}` | Prepare one advertised frame if absent and return it or a deduplicated job. By default use one exposure. A separate explicit `representation: "coadd"` may prepare up to four compatible exposures in that visit within the same job ceiling, with its own variant ID and contributor metadata. Record alternative products actually used when a provisional source fails. |
| `POST /api/v1/series/{seriesId}/comparisons` | `frameA`, `frameB`, `mode` in `difference`, `absolute_change`, `residual_score`, or `sum`. Two loaded compatible frames in the same grid. Return the rendered overlay, mask/coverage, units, stretch and provenance. Blink/side-by-side can use existing image payloads. |
| `POST /api/v1/series/{seriesId}/detections` | Bounded explicit `frameIds` or an existing `comparisonId`, plus optional in-grid `region`. Return confidence/quality flags, signed feature metadata or matched peaks, and source classification evidence. Use prepared arrays and limit results. |
| `POST /api/v1/series/{seriesId}/tracks` | `candidateId` for an existing linked candidate or `marks` with frame IDs and pixel or sky coordinates, plus optional `horizonDays`. Verify sky/time against frame metadata, use one position per independent visit, and return measured motion, associations, and forecast status with uncertainty. Time comes from the observations. |
| `POST /api/v1/series/{seriesId}/overlays` | `catalog` in `gaia_dr3` or `allwise`, plus optional `frameId` for the display epoch. Bounded cone/row result with a completeness flag. Cache catalog rows independently of playback and transform locally. |
| `POST /api/v1/series/{seriesId}/spectra` | One `selectedSkyPosition` or `candidateId`, `timeRange`, optional `wavelengthRange`, `method` such as `epsf` or `aperture`, and `mode` in `quick`, `extended`, or `coadded_cube`. Return calibrated samples and gaps with dates, units, uncertainties, and source links. Permit a partial spectrum when the session budget is reached. |
| `GET /api/v1/jobs/{jobId}` | `queued`, `running`, `succeeded`, `partial` or `failed`; include stage, endpoint-relative result link or error, and retry/poll advice. Clients stop polling on completion, tab closure, or deadline. |

Use a ready envelope `{status, data, warnings}` with `status` set to `succeeded` or `partial`. Use HTTP 202 with `{status, jobId, pollAfterMs}` for accepted work and `{code, message, retryable, retryAfterSec?}` for errors. A completed job returns the same ready envelope directly or a result link to a stable resource that returns it. It must never require replaying the original POST to fetch a result. Over-budget requests return a documented validation or rate error. Partial archive metadata, masked coverage and insufficient independent epochs can accompany successful data. Responses document UTC times, detector, physical units and version. The service may return a bounded partial result with a smaller follow-up request.

### Manifest and assets

- **Series.** `schemaVersion`, `seriesId`, `query` (ICRS coordinates in degrees, dimensions in arcminutes, UTC range and band), `grid` (TAN projection, CRPIX, CRVAL, CD matrix or equivalent, width and height), `counts`, `searchStatus` and per-collection warnings, sources/releases and pipeline version. Carry the discovery bounds and completeness separately from prepared frame counts.
- **Timeline entry.** `frameId`, `slotKey`, `visitId` if known, actual UTC time/time range, product IDs, detector and calibration release, wavelength/width status, provisional footprint and load/quality state. Coadds carry contributor count and dates. An omitted asset means it has not been prepared or is unavailable. A slot is not a measured independent epoch by itself.
- **Prepared frame.** Add actual footprint and quality flags, image and mask artifact URLs, WCS and pixel convention, brightness units, stretch, observed bandpass, and archive DOI/product references. Measurement IDs, comparisons and annotations point at these frame IDs and pipeline versions. Content-hashed PNG or WebP is for display. Keep calibrated value/variance/coverage arrays server-side for analysis.
- **Persistence.** Generate immutable versioned presets and a matching static manifest at build/release time. Live request keys include normalized center/grid, field width, date range/band, product or visit IDs and pipeline version. Store versioned derived images atomically; an evicted cached live frame can be regenerated from its verified source within the same budget. Raw archives, caches and job state stay outside Git. Browser analytical selections and marks are local unless the visitor opts to include them in a shared link.

### Links and reproducibility

A link carries normalized `ra`, `dec`, `fov`, selected range, interval and band, plus stable product/date selectors for A/B and view mode when available. A pinned comparison link can include the relevant versioned identifiers and at most two marks with sky coordinates and frame references. Prefer catalog/product identifiers to ephemeral job IDs. Keep links bounded and URL-encode them. When a pinned product is missing, show the reason and offer to rediscover the field. Strip credentials and never use arbitrary URL parameters as fetch targets.

## 4. Integration acceptance

- **Time views:** synthetic fixture with multiple detectors on one pointing, multiple pointings/day, two adjacent dates from one visit, long gaps, missing dates and partial metadata. Verify exact dates, counts, 7/30-day bucket boundaries, keyboard navigation, labels, direct-link recovery and one-frame behavior.
- **Network and load:** a rapid complete scrub issues no uncached requests per pointer move, only bounded commits/adjacent low-priority work. Drive concurrent users and confirm queue saturation, no archive request stampede, bounded metadata/bytes, old responses being ignored, and a fast preset fallback during simulated 502s.
- **Comparisons:** use two real compatible observations and a synthetic known change. Validate same-grid side-by-side and blink, color sign and no-data mask, automatic detection and uncertainty states, and mark separation/error with known coordinates. A pair with poor alignment or incompatible bandpasses must not produce a ranked detection or forecast.
- **Public browser:** Go from new coordinates to first real frame, change interval, drag and step, toggle overlays, use spectrum and tracking only when supported, and open the same link in a fresh browser. Inspect desktop and mobile screenshots. Verify all five sample outcomes and a valid covered non-preset query from outside the development host.
