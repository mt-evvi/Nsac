# SPHEREx comparison, detection, trajectories and spectra

This specification extends [BUILD_PLAN.md](../BUILD_PLAN.md). Its numeric science thresholds are starting points to tune on injected and real data. The [viewer contract](VIEWER_AND_API.md) defines the job envelope. [Production and budgets](PRODUCTION_AND_BUDGETS.md) defines the enforced limits.

## Shared inputs

Resolve requests to versioned frames in one series. A frame carries observation midpoint and time range in UTC, contributing exposure IDs, detector, release, calibration version, pixel size, ICRS TAN grid, and provenance. Keep calibrated surface brightness in MJy/sr, wavelength, coverage, validity and finite positive variance in bounded server arrays. Derive PNGs separately. Fit centroids and calibrated photometry on the native grid and effective point spread function (ePSF) wherever available. Track independent visits instead of treating long coadds or simultaneous detector reads as separate motion measurements.

Use the product-specific FLAGS definitions. Exclude invalid, saturated, cosmic ray and major artifact pixels under the recorded policy. The SOURCE flag alone must preserve usable science pixels and may exclude them from the background fit. Account for zodiacal background consistently because the ZODI model is supplied separately. Retain background, relative scale, registration and PSF diagnostics. Use the fixed view grid for overlay geometry so zoom and pan stay synchronized. [SPHEREx products](https://caltech-ipac.github.io/spherex-archive-documentation/spherex-data-products/) · [Explanatory Supplement](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/SPHEREx_Expsupp.pdf)

## Blink, side-by-side, signed heatmap and sum

1. **Select a pair.** Let users pin A and B and inspect both timestamps. Require independent visits, sufficient valid overlap, and compatible wavelength passbands for quantitative comparison. Start with the same detector and an overlap of at least 50% of the narrower passband. Bound the central wavelength offset by half the narrower bandwidth. Use the spectral map at every analyzed pixel to mask mismatch across the field. WCS-WAVE is suitable for a quick look. CWAVE and CBAND are for calibrated analysis. A detector ID alone is insufficient. Allow visual inspection of mismatched images with a clear wavelength warning.
2. **Register.** Align once to the same north-up sky grid near the native scale. Propagate variance using squared interpolation weights and preserve a conservative validity footprint. Refine a relative offset only with vetted stable reference sources, keeping before/after residuals. A starting candidate-ranking gate is at least three usable references and a robust relative residual below 0.3 native pixel. Without those references the nominal WCS can still give a visual comparison, with relative astrometric precision unverified. Recentring on each target would erase its measured motion.
3. **Match background, scale and resolution.** Estimate background and any relative scale using common valid sky and vetted stable sources. Mask contaminated pixels, target and bright cores during these fits. Use a validated local kernel to match both images to a common broad ePSF. Convolve variance with squared kernel weights and expand the invalid mask over affected neighborhoods. Keep imperfect fits visible as warnings and suppress automated candidate promotion if alignment or ePSF matching fails. Independent display contrast changes must never feed quantitative analysis.
4. **Render the difference.** Compute D = B′ − A′ from matched values. Show a zero-centered diverging legend in MJy/sr, positive for brighter in B, negative for fainter. Use a robust symmetric range with an optional display clamp. Make masked pixels visible as missing. Add an absolute-change mode and an approximate residual score D / sqrt(VA′ + VB′ + Vmodel) when supported. Resampling induces correlated noise. Estimate a correction from source-free stable data and label uncalibrated scores as heuristic, with no formal p-value. A signed doublet can suggest movement and a single residual can suggest variability. Both have potential artifact explanations.
5. **Sum separately.** Show A′ + B′ on common valid pixels with the inputs, units and dates identified. A deeper reference can use an independently labeled inverse-variance-weighted mean of near-simultaneous compatible exposures. List contributing exposures and the time range. Long coadds can smear motion. Blink and side-by-side share one contrast stretch and the same grid.

**API:** `POST /api/v1/series/{seriesId}/comparisons` with `{frameA, frameB, mode}` returns or queues a result with comparison ID, ordered frame IDs, asset URL, units and limits, overlap/mask fraction, plus registration and wavelength quality. Include the score/matching method in metadata. Cache by ordered pair, settings, mask policy and pipeline version. Compute only the selected pair. Track one comparison request per viewer and keep the raster at the same maximum 128 × 128 science grid as the inputs. Blink and flipping cached images issue no IRSA requests. [IRSA source discovery notebook](https://caltech-ipac.github.io/irsa-tutorials/spherex-source-discovery-tool-demo/) · [Image-differencing methods and assumptions](https://doi.org/10.3847/0004-637X/830/1/27)

## Automatic object recognition

- **Detect.** Use Photutils or a small PSF template with robust local background and noise. Detect native-frame point sources and positive and negative residual groups independently. Start at 5× the measured robust noise in the relevant detection statistic and require PSF-like spatial support or a successful native ePSF fit. Exclude frame edges and obvious flags. Return measured position, covariance, brightness, S/N, mask proximity, residual sign and fit diagnostics. Consider calibrated difference detections only when the pair passes its quality gate.
- **Associate.** Convert detections to one celestial tangent plane. Use a KD-tree or spatial bins for local matches. Gate by position covariance, elapsed time and configured maximum apparent speed. Assign at most one detection per independent visit. Resolve unique matches first with deterministic gated assignment, preserve competing feasible associations as ambiguous, and treat gaps as missing evidence. Require a predicted counterpart to fall on usable pixels with comparable wavelength and sensitivity before penalizing a missing detection.
- **Classify and rank.** Distinguish a motion candidate, possible variable, single-pair change, likely artifact, and ambiguous candidate. Show the evidence behind each label. Rank using S/N, quality, independent clean visits, and association ambiguity. A repeated flux change with consistent astrometry can suggest variability. A repeated significant offset with an unambiguous fit can suggest motion. Catalog proximity is a separate identity suggestion. An uncatalogued point or a residual in one pair cannot establish a planet, comet, or asteroid. Let users accept, move or dismiss a detection as a mark. A quiet field can legitimately show no candidates.

**API:** `POST /api/v1/series/{seriesId}/detections` with `{frameIds OR comparisonId, region?}` returns an analysis ID and candidates with per-visit detections, covariances, label, reason, ambiguity, provenance and nearby catalog matches if loaded. Limit to eight prepared independent visits, 50 ranked candidates per visit, and 100 linked candidates in total. Reuse analysis for immutable inputs. Run on demand with one job per viewer, bounded fit iterations and no remote model calls or new FITS fetch to rank loaded frames. Surface partial coverage if parameters exceed a limit. [Photutils detector](https://photutils.readthedocs.io/en/stable/api/photutils.detection.DAOStarFinder.html) · [Photutils PSF photometry](https://photutils.readthedocs.io/en/stable/user_guide/psf.html)

## Mark and compare, and possible future path

**Mark on the two dates.** Keep the raw zero-based image-pixel marks and their reproducible frame IDs. Invert the viewer’s zoom, pan and raster scaling before converting through the manifest WCS. Use the same TAN pixel-center convention in TypeScript and Astropy and test their agreement. Targets snapped to an existing detection carry its measured centroid and covariance, while the original mark remains available. Require different independent visits and valid pixels. Display ICRS coordinates, dates, great-circle angular separation, position angle east of north, baseline and apparent angular speed, with precision proportional to measurement quality. Human clicks get an error floor estimated from repeat clicks and view scale. A share or export stores the frame IDs, original marks, method, sky coordinates and uncertainty. [Astropy sky separations](https://docs.astropy.org/en/stable/coordinates/matchsep.html)

**Fit an unknown candidate.** With two visits report the measured motion vector. Allow an extrapolation only if at least three independent usable visits give a unique, well-conditioned track and significantly resolved angular motion. Fit both tangent-plane coordinates with weighted least squares about a weighted reference epoch: position = intercept + velocity × time offset. Propagate centroid, relative registration and mark errors through a two-coordinate covariance. Include a conservative systematic floor if shared errors cannot be modelled. Check the fit against a stationary model and against per-visit residuals. An initial gate is speed exceeding three times its uncertainty with standardized residuals within a verified range. With three visits keep them all or report the failed fit. Ambiguity, curvature or insufficient baseline shows the measurements and an explanation.

**Display a bounded extrapolation.** Transform predicted points and errors to ICRS. Use a dashed line and visibly distinct uncertainty. Propagate parameter covariance with the time-dependent design matrix and the systematic floor. Use an approximate 95% two-dimensional ellipse only with validated covariance. Label other uncertainty bands as heuristic. Cap at 25 samples within the smaller of 30 days or half the observed baseline. Stop at the field boundary or when the error region exceeds a configured size, starting at one quarter of the field width. Label it an *apparent sky path*. Angular positions alone leave distance, parallax, acceleration and orbital parameters underdetermined. A separate acceleration model would require at least four independent visits, detectable curvature and verified out-of-sample accuracy. Keep it off by default.

**Use known-object models when justified.** Propagate a firmly associated Gaia stellar reference with the catalog’s actual epoch and covariance; mark it as a catalog model. Add parallax to a predicted apparent position only with the correct observer geometry. For a confirmed Solar System identifier use an offline, verified ephemeris or link to official Horizons/IRSA MOST. Include source, observer location, frame and timescale. A geocentric solution can provide context, while an astrometric check needs the correct SPHEREx observer. JPL SSD prohibits embedding its APIs in websites. If later commissioning approved integration, follow provider policy, including serialized requests, valid contact User-Agent, caching and backoff. [Gaia DR3 schema](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_main_source_catalogue/ssec_dm_gaia_source.html) · [IRSA MOST](https://irsa.ipac.caltech.edu/applications/MOST/instructions.html) · [Horizons](https://ssd.jpl.nasa.gov/horizons/manual.html) · [JPL API fair use](https://ssd-api.jpl.nasa.gov/doc/index.php)

**API:** `POST /api/v1/series/{seriesId}/tracks` with `{candidateId OR marks, horizonDays?}` resolves original frames and returns measured points, baseline, separation, position angle, speed, errors, and an optional forecast containing samples, model, validity horizon, assumptions and uncertainty. Failed quality gates return reason codes such as too few epochs, unresolved motion and ambiguous association. Allow at most eight independent input visits. Marks, motions and forecasts on loaded data require zero archive downloads.

## Catalog overlays

Provide independently toggleable Gaia DR3 and AllWISE marker layers. Query only a validated cone around the field, with a small bounded halo for proper motion. Filter projected markers to the displayed view. Treat catalog IDs as strings and retain native ICRS position, reference epoch, quality and proper motion/parallax where available. Gaia stores pmra with cos(Dec) already applied. Display AllWISE at its documented historical epoch unless the selected astrometric solution supports propagation. Associations show separation, catalog and date, and distinguish crowding or multiple plausible matches. An optional Aladin Lite context panel should use the same field center and pass mobile and coordinate checks before shipping.

**API:** `POST /api/v1/series/{seriesId}/overlays` with `{catalog, frameId?}` returns markers, display epoch, catalog provenance, position method and truncation. Cache rows by field and catalog, then calculate their positions for already loaded epochs in memory. Load on explicit toggle and field changes. Use at most 200 rows and two query attempts per catalog, and clearly label truncation. A catalog outage does not affect the viewer or slider. [Gaia DR3 astrometry](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_main_source_catalogue/ssec_dm_gaia_source.html) · [AllWISE catalog API](https://irsa.ipac.caltech.edu/onlinehelp/catalogs/catalogs/api.html) · [AllWISE astrometry](https://irsa.ipac.caltech.edu/data/WISE/docs/release/AllWISE/expsup/sec5_3bii.html) · [Aladin Lite](https://aladin.cds.unistra.fr/AladinLite/doc/)

## Spectra and wavelength-matched brightness

1. Start an explicit job from one selected sky position or candidate. For movers use measured native positions per exposure to avoid treating a stationary sky pixel as the object. Work in a defined date and wavelength range and retain separate epochs for moving or variable sources.
2. Check exposure quality, then map cutout pixels to the calibrated detector coordinates and read CWAVE and CBAND with the correct calibration version. Select the matching native ePSF or use a calibrated aperture and local annulus. Reject invalid backgrounds or apertures with insufficient support. Use the detector solid-angle map to convert surface brightness to flux density for pixel sums, or follow the documented native ePSF normalization. Preserve independent variance and background uncertainty. Give upper limits only when the noise method is documented.
3. Plot measured flux and uncertainty across the covered wavelengths, with individual exposure and wavelength widths available. Show gaps, masked samples and contextual limits. Combine consistent samples using documented weights and time spans only. Render matched-wavelength flux against actual UTC times for a light curve and avoid estimating a period from sparse points.
4. A separate quick-look DR1 cube tab can supply nominal 102-channel coadded spectral context, including blank channels. Serve a precomputed target extract or range-read only the required local samples under a byte cap. A 512 × 512 × 102 FITS cube tile is large even though it covers a small part of the sky. Respect the archive’s documented blank channels 51 and 52. Keep the cube in a spectral context panel with no date interpolation. Cite the cube DOI when used. [DR1 product citation](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/overview_dr1.html)

**API:** `POST /api/v1/series/{seriesId}/spectra` with `{selectedSkyPosition OR candidateId, timeRange, wavelengthRange?, method, mode}` returns samples with UTC time, wavelength, bandwidth, flux, error, units, quality, exposure ID and calibration IDs, and coverage and truncation. Cache by selection, exposures, calibration, time bounds and pipeline version. Use one source and the eight-sample quick mode or explicit extended mode capped at 32 samples, subject to stream and time limits. Reuse versioned calibration locally. Download calibration only as bounded shared background work. Return partial results and actual gaps instead of acquiring every possible cutout. [IRSA spectrophotometry tool](https://irsa.ipac.caltech.edu/onlinehelp/spherex/spherex/sp.html) · [IRSA HiPS cube notebook](https://caltech-ipac.github.io/irsa-tutorials/spherex-hipscube/) · [SPHEREx calibration products](https://caltech-ipac.github.io/spherex-archive-documentation/spherex-data-products/)

## Verification gates

| Feature | Evidence before release |
|---|---|
| Heatmap and sum | An identical synthetic input pair gives a valid zero difference to a measured tolerance and the expected sum. A flux change has the correct sign, reversing A and B reverses the map, and a translated point yields the expected signed doublet. Masked, locally wavelength-mismatched and edge pixels cannot produce ranked residuals. Record registration error, residual noise and false positives on a stable real field. |
| Candidate recognition | Inject moving, fixed variable and unchanged sources, a cosmic ray, crowded associations and masked gaps. Verify classifications and report measured precision and recall on labeled fixtures by S/N. Include at least one real field with a documented reference. A detection is never validated by injection alone. |
| Marks and future path | Verify RA wrap, sky position angle, manual uncertainty, same-visit rejection and masking. On a four-epoch fixture fit the first three, forecast the withheld fourth and check error bounds. Verify that two visits yield the motion vector, ambiguous objects give a fit status, and poor fits suppress predictions. Check any known-object path against its ephemeris with identical observer, frame and timestamps. |
| Overlays and spectra | Verify reference epoch and proper-motion transforms, date navigation, dense and empty fields, truncation and attribution. Compare one calibrated spectrum with IRSA forced photometry using consistent position, epochs, wavelengths and background. Declare the tolerance before comparison. Verify missing bins, units, errors, an actual calibrated flux sample and a budget-limited partial job. |
| Workload and UI | Measure cold and repeated request bytes, time, cache keys and cancellation on sparse and crowded fields. Scrubbing may request a bounded frame asset, but does not trigger heatmap computation, catalog lookup, detection, tracking or spectrum work. Use desktop and mobile browser checks for compare controls and legend, candidate keyboard selection, shared marks, track uncertainty, catalog attribution and spectrum gaps/errors. |
